# PeopleFlow — HRM + Employee Learning

MVP ภาษาไทยสำหรับแพลตฟอร์มหลายบริษัท สร้างด้วย **Next.js App Router, TypeScript และ PostgreSQL**
แนวทางฟังก์ชันและรูปแบบแอปบริหารบุคคลอ้างอิง HumanSoft แต่ใช้ชื่อ ดีไซน์ และโค้ดของโครงการเอง

## เริ่มใช้งานในเครื่อง

ต้องมี Node.js 24 และ pnpm 11.25.0 (`corepack enable` หากเครื่องรองรับ)

```sh
pnpm install --frozen-lockfile
pnpm run setup
pnpm db:migrate
pnpm db:seed
pnpm dev
```

เปิด <http://localhost:3000> ใช้ `localhost` ให้ตรงกับ `AUTH_URL` และ OAuth callbacks

`pnpm run setup` สร้าง `.env` ด้วย AUTH_SECRET และ SEED_PASSWORD แบบสุ่ม ไม่แก้ไฟล์ที่มีอยู่แล้ว
คำสั่งต้องใช้ **`pnpm run setup`** เพราะ `pnpm setup` เป็นคำสั่งของตัว package manager

บัญชีทดสอบ (รหัสผ่านคือค่า **SEED_PASSWORD ใน `.env`**):

| บัญชี               | บทบาท                       |
| ------------------- | --------------------------- |
| admin@bloom.demo    | ผู้ดูแลระบบ ใช้ได้ 2 บริษัท |
| hr@bloom.demo       | HR / ผู้จัดทำหลักสูตร       |
| manager@bloom.demo  | หัวหน้างาน                  |
| employee@bloom.demo | พนักงาน                     |

ข้อมูลตัวอย่างประกอบด้วยบริษัท Bloom และ Northstar พนักงาน 6 คน แผนก ตำแหน่ง กะ คำขอ และหลักสูตร 3 ชุด
Northstar เริ่มว่างเพื่อทดลองการแยกข้อมูล ส่วนหลักสูตรเป็นข้อความตัวอย่าง ไม่ใช่นโยบายบริษัทจริง
Seed จะไม่ทับข้อมูลเมื่อมีบริษัทแล้ว ควรรัน migrate/seed ก่อนเปิด dev server

### ฐานข้อมูล

ค่าเริ่มต้นใช้ **PGlite (PostgreSQL ผ่าน WASM)** เก็บลง `data/peopleflow` ข้อมูลอยู่ต่อหลังปิดแอป
เหมาะสำหรับการทดลองแบบ **หนึ่ง Node process เท่านั้น** ห้ามให้ dev/start/migrate/seed เปิดไฟล์ฐานข้อมูลเดียวกันพร้อมกัน
ทดสอบอัตโนมัติใช้ฐานข้อมูลแยกในหน่วยความจำ ไม่แตะข้อมูลใช้งาน

สำหรับ PostgreSQL ปกติ:

```sh
docker compose up -d
```

ตั้ง `DATABASE_URL=postgres://peopleflow:peopleflow@localhost:5432/peopleflow` ใน `.env`
แล้วรัน `pnpm db:migrate` และ `pnpm db:seed` ใหม่ ฐานข้อมูลสองแบบไม่ย้ายข้อมูลให้กันอัตโนมัติ
รหัส Docker ค่าเริ่มต้นใช้สำหรับ local เท่านั้น เปลี่ยน POSTGRES_PASSWORD และ URL ให้ตรงกันก่อนใช้ที่อื่น

## ฟังก์ชันที่ทำงานได้

**Phase 2:** เพิ่มเส้นทางเรียน เช็กลิสต์ทักษะ หลักสูตรหลายเวอร์ชัน แจ้งเตือนในแอป และอัปโหลด private PDF/วิดีโอ ดู [คู่มือ Phase 2](docs/phase2.md)

- **หลายบริษัท:** สลับบริษัทตาม membership, สร้างบริษัทใหม่โดย admin, ตรวจสิทธิ์ใหม่ทุก server action
- **HRM:** เพิ่ม/แก้ข้อมูลพนักงาน แผนก ตำแหน่ง สาขา หัวหน้างาน วันเริ่มงาน ทดลองงาน ผ่านงาน/พ้นสภาพ
- **เวลาและกะ:** ลงเวลาเข้า/ออกด้วยเวลาฝั่งเซิร์ฟเวอร์, ประวัติ 60 วัน, สร้างกะและมอบหมายตามวัน
- **ลา / OT:** พนักงานยื่นคำขอ ผู้มีสิทธิ์อนุมัติหรือปฏิเสธ พร้อมหมายเหตุ ไม่อนุมัติตนเอง
- **การเรียนรู้:** ร่างหลักสูตร บทเรียนข้อความ/วิดีโอ URL/เอกสาร URL แบบทดสอบ คะแนนผ่าน และเผยแพร่
- **มอบหมายอัตโนมัติ:** ตามตำแหน่งหรือทุกตำแหน่ง เมื่อเพิ่มพนักงาน เปลี่ยนตำแหน่ง หรือเผยแพร่หลักสูตร
- **เรียนและสอบ:** บันทึกบทที่เรียนครบ ตรวจข้อสอบจากเซิร์ฟเวอร์ เก็บประวัติสอบและคะแนนสูงสุด
- **สอบไม่ผ่าน:** ต้องทบทวนบทเรียนและยืนยันใหม่ก่อนสอบซ้ำ ไม่ลบประวัติสอบ
- **ตรวจรับทักษะ:** หัวหน้าสังเกตการทำงานจริงและบันทึกหลักฐานหลังผ่านข้อสอบ ก่อนขึ้นสถานะพร้อม
- **ผู้ช่วยคู่มือ:** ค้นเฉพาะบทเรียนที่ผู้ใช้ได้รับมอบหมาย แสดงแหล่งข้อมูล; เปิด AI ได้ด้วย env
- **การเชื่อมต่อ:** Google/Microsoft OAuth, API รับข้อมูลเครื่องลงเวลา, LINE Messaging API, accounting CSV adapter
- **ประวัติรายการ:** บันทึกการเปลี่ยนข้อมูล อนุมัติ ผลสอบ ตรวจรับทักษะ และการส่งออก

## สิทธิ์

| บทบาท    | ขอบเขต                                                          |
| -------- | --------------------------------------------------------------- |
| Admin    | ข้อมูลทั้งบริษัท สร้างบริษัท ตั้งค่า integration และ audit      |
| HR       | จัดการพนักงาน โครงสร้าง หลักสูตร อนุมัติ/ตรวจรับ ส่งออกข้อมูล   |
| Manager  | ดูตนเองและลูกทีมโดยตรง จัดกะ/มอบหมาย/อนุมัติ/ตรวจรับเฉพาะลูกทีม |
| Employee | ดูตนเอง ลงเวลา ยื่นคำขอ เรียนและสอบของตนเอง                     |

HR และ Admin ตรวจรับ/อนุมัติตนเองไม่ได้ พนักงานพ้นสภาพจะเข้า membership ของบริษัทนั้นไม่ได้ แม้ยังมี session
การเรียนและสอบทุกบทบาททำได้เฉพาะ enrollment ของตนเอง เฉลยข้อสอบไม่อยู่ใน payload ที่ส่งให้ browser

## การเชื่อมต่อบริการภายนอก

ดู [docs/integrations.md](docs/integrations.md) สำหรับ env, callback URL, ตัวอย่าง payload และวิธีเพิ่ม adapter
**ยังไม่ได้ทดสอบกับบัญชี Google/Microsoft, LINE bot, API key AI หรือเครื่องสแกนจริง** เพราะยังไม่ได้รับการตั้งค่า
DemoScan และ DemoLedger เป็นชื่อสมมติสำหรับแสดงวิธีเปลี่ยนผู้ให้บริการ

## ขอบเขต MVP และข้อจำกัด

- ไม่มี payroll/ภาษี/สวัสดิการ/สรรหา ตาม scope ระยะแรก ไม่มีการสร้างยอดเงินบัญชีจากชั่วโมงโดยสมมติอัตราค่าจ้าง
- ลาแบบเต็มวัน นับ **วันปฏิทิน** ตรวจพักร้อนตามสิทธิ์เริ่มต้น 6 วันต่อปี ไม่มีวันหยุดบริษัท/ครึ่งวัน/ยกยอด/อายุงาน
- อนุมัติ **1 ขั้น**; ป่วย/กิจให้ผู้อนุมัติพิจารณา ยังไม่คำนวณโควตานโยบายเฉพาะบริษัท
- หนึ่งรายการเวลาเข้า/ออกต่อพนักงานต่อวัน การออกกะข้ามคืนอ้างอิงการเข้าใน 24 ชั่วโมงที่ผ่านมา; ไม่มี GPS/ชีวมิติ/ป้องกันลงเวลาแทน
- หัวหน้างานดูเฉพาะลูกทีมตรง ไม่ขยายสายบังคับบัญชาอัตโนมัติ
- บทเรียนยืนยันการอ่านโดยผู้เรียน ยังไม่บังคับดูวิดีโอจนจบและยังไม่มี SCORM (Phase 2 เพิ่มอัปโหลด PDF/วิดีโอแบบ private แล้ว)
- วิดีโอลิงก์ MP4/WebM/Ogg เล่นในหน้าได้ ลิงก์ผู้ให้บริการอื่นเปิดแท็บใหม่ เอกสาร URL เปิดจากแหล่งเดิม
- หลักสูตรเผยแพร่แล้วแก้บทเรียน/ข้อสอบไม่ได้ ใช้สร้างเวอร์ชันใหม่เพื่อรักษาเกณฑ์ของผู้เรียนเดิม
- มีบัญชีเริ่มต้น/สร้างพนักงานโดย HR ไม่มี public signup, email invite, forgot password, MFA, billing หรือ subscription
- ใช้ Auth.js v5 beta; ล็อกเวอร์ชันใน lockfile และควรประเมินอัปเกรดก่อนเปิดบริการจริง
- Google/Microsoft ใช้บัญชีที่จัดเตรียมไว้เท่านั้น ไม่เพิ่มสมาชิกตามโดเมนอีเมลโดยอัตโนมัติ
- AI ไม่เปิดจนตั้ง key และ model; โหมดไม่มี key เป็น **การค้นข้อความ** ที่ระบุชัด ไม่อ้างว่าเป็น AI
- LINE ส่งเมื่อ admin กด ไม่มี scheduler/queue/retry หรือ notification อัตโนมัติใน background
- ระบบบัญชีเป็น CSV ส่งต่อข้อมูล ยังไม่เชื่อม API ของผู้ให้บริการเฉพาะราย
- UI ใช้ font ออนไลน์ถ้าเข้าถึงได้ และมี Thai system font สำรอง

โครงสร้างและแนวทางพัฒนาต่ออยู่ที่ [docs/architecture.md](docs/architecture.md)
ก่อนเปิด SaaS จริงควรเพิ่มการสำรอง/กู้คืน ฐานข้อมูลแยกจากแอป pagination, monitoring, การทดสอบโหลด,
การจัดการความลับแยกบริษัท และการตรวจความปลอดภัย/นโยบายข้อมูลตามสภาพแวดล้อมจริง
